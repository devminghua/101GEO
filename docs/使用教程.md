# LinkGeo 系统使用教程

> 系统全称：LinkGeo（GEO 智能监测与优化 SaaS）
> 访问入口：http://127.0.0.1:8080
> 文档更新：2026-09-02

---

## 一、系统是干什么的（一句话原理）

**LinkGeo 是一套「监测品牌在 AI 回答里是否被提及」的 SaaS 系统。**

传统 SEO 看的是搜索引擎排名（百度/Google 第几位）。而 GEO（Generative Engine Optimization，生成式引擎优化）看的是：**当用户向 AI（DeepSeek、豆包、通义千问、智谱、Kimi 等）提问时，AI 的回答里有没有提到你的品牌/产品。**

系统做的事，一句话概括：

> 你配好「问题 + 品牌词」→ 系统逐个 AI 平台自动提问 → 检测 AI 回答里是否出现你的品牌词 → 统计「出现率 / 覆盖率 / 排名」→ 生成报告告诉你该在哪铺内容。

## 二、核心原理（怎么工作的）

### 2.1 完整巡检链路

```
配置关键词（问题 + 品牌词）
        │
        ▼
发起巡检（手动 or 定时 8-22 点每小时自动）
        │
        ▼
对每个「关键词 × 启用平台」组合，逐个向 AI 提问
        │
        ▼
解析 AI 回答，检测品牌词是否命中（含出现位置、出现次数）
        │
        ▼
扣点计费（每次 AI 调用扣 1 点）
        │
        ▼
生成报告 + 仪表盘（覆盖率 / 出现率 / 排名分布 / 各平台表现）
```

### 2.2 关键概念解释

| 概念 | 含义 | 例子 |
|---|---|---|
| **关键词（监控词）** | 你要监测的「问题 + 期望被提及的品牌词」 | 问题「婚恋源码」、品牌词「link婚恋系统」 |
| **命中（hit）** | AI 回答里出现了你的品牌词 | 回答含「link婚恋系统」→ 命中 |
| **未命中（miss）** | AI 回答里没提你的品牌词 | 回答只讲婚恋源码，没提你的品牌 → 未命中 |
| **覆盖率（coverage）** | 有多少个平台「API 已打通且成功返回」 | 5 个启用平台都通 → 覆盖 5 |
| **出现率 / 可见度（visibility）** | 命中数 ÷ 查询总数的百分比 | 10 次查询命中 5 次 → 37.3%（含历史） |
| **排名（position）** | 品牌词第几次出现在 AI 回答里 | 第 2 句就提到 → position 2 |

> **要点**：GEO 监测的意义在于，你会发现「品牌词出现在问题里，AI 会复述（看似命中）」，但「真正想让 AI 主动推荐的品牌，AI 往往不提（未命中）」。未命中的问题，就是你要去铺内容（知乎/公众号/官网结构化内容）的目标。

### 2.3 多租户隔离架构

```
┌─────────────────────────────────────────────┐
│  总后台（super，账号 admin）                 │
│  统一开户 / 配 AI 平台 / 充值 / 看全局       │
└──────────────────┬──────────────────────────┘
                   │ 一个客户 = 一个分站（tenant）
        ┌──────────┼──────────┬─────────────┐
        ▼          ▼          ▼             ▼
   分站 A      分站 B      分站 C      分站 D
   (demo)    (轻媒婚恋)  (LINKCRM)   (佳缘婚恋)
   admin     admin      admin       admin
        │
        ▼
  每个分站独立配置关键词、独立点数、独立报告，数据完全隔离
```

- **角色权限**：`super`（总后台，管所有）、`admin`（分站管理员，管本租户）、优化员（只读+执行，无配置权限）。
- **登录账号**：总后台 `admin`；每个分站一个 `admin` 账号（自助注册时账号 = 手机号）。
- **数据隔离铁律**：分站之间、分站与总后台之间，关键词/点数/报告完全隔离，互不可见。

### 2.4 点卡计费机制

- 每次 AI 巡检调用 **扣 1 点**（`type=consume`，备注「GEO 智能巡检」）。
- 点卡余额不足时无法发起巡检。
- 总后台可为分站 **充值**（`recharge`）；分站管理员可 **自助扫码充值**（微信/支付宝下单）。
- 服务有 **有效期**（天数），到期需续费才能继续使用。
- **自助注册** 自动开通：**7 天试用 + 100 点**。

## 三、使用步骤（怎么用）

### 第一步：总后台配置（super / admin 账号）

1. 浏览器打开 `http://127.0.0.1:8080`，用总后台账号登录（账号 `admin`）。
2. 左侧进入「**AI 平台**」：查看/启停各平台，填 API Key 与模型名，点「测试」确认平台 API 已打通。
   - 当前启用：DeepSeek、豆包、通义千问、智谱 GLM、Kimi。
   - 停用（Key 未通/无服务）：腾讯混元、OpenAI、Ollama。
3. 左侧进入「**客户/分站**」：为每个客户创建一个分站（自动生成分站 admin 账号与初始点数）。

### 第二步：分站配置监控关键词

1. 用分站账号登录（如 demo / `link0921`）。
2. 进入「**关键词 / 监控词**」模块，添加监控词，每条包含：
   - **问题**：用户会向 AI 问什么（如「婚恋源码」「推荐一下XX品牌」）。
   - **品牌词**：期望 AI 回答里出现的你的品牌名（如「link婚恋系统」）。

### 第三步：发起巡检

1. 在关键词页点击「**立即巡检**」（手动），或由系统 **定时自动巡检**（每天 8:00–22:00 每小时一轮，对所有启用分站）。
2. 系统会按「关键词 × 启用平台」逐个向 AI 提问，任务列表实时显示进度（总查询数、命中、未命中、错误）。

### 第四步：查看报告与仪表盘

1. 「**仪表盘**」：总览 KPI（可见度、覆盖率、平台覆盖横幅、排名监测 TOP10、排名分布）。
2. 「**报告**」：按周期生成 Markdown 报告（总览 / 各平台表现 / 各问题表现 / 优化建议），可导出。
3. 「**任务明细**」：看每一条查询的 AI 原始回答、是否命中、命中位置、耗时。

### 第五步：充值 / 续费

- 总后台「客户 → 充值」给分站加点；分站管理员「点卡中心」自助扫码充值。
- 试用到期（默认 7 天）或点数用尽，需充值/续费。

### 第六步：自助注册（手机号 + 短信验证码）

1. 登录页点「**立即注册（免费试用）**」，或直接访问 `http://127.0.0.1:8080/#/register`。
2. 输入手机号 → 点「获取验证码」→ 输入 6 位验证码 → 设密码 + 公司名 → 提交。
3. 注册成功即 **自动创建新分站 + admin 账号**（账号 = 手机号），**自动开通 7 天试用 + 100 点**，并直接登录。
4. 验证码规则：5 分钟有效、同号 60 秒冷却、一次性校验。
   - **当前为 Mock 联调阶段**：验证码不会真发短信，而是通过接口响应 `debug_code` 字段返回（也打印在后端日志），联调用。接真实短信服务商（阿里云）后替换。

本次对系统做了一次从「登录 → 巡检 → 命中检测 → 扣点 → 报告」的端到端全链路检验，结论 **全部跑通**：

|---|---|
| 服务健康 | 容器 Up，首页/系统信息 HTTP 200，系统名「LinkGeo」 |
| 登录认证 | admin(super) 与 demo 均登录成功（含滑块验证） |
| AI 平台配置 | 5 个启用平台、3 个停用，配置读取正常 |
| 分站数据 | 4 个分站（demo/轻媒婚恋/LINKCRM/佳缘婚恋）隔离正常 |
| 发起巡检 | task#37 成功执行（2 关键词 × 5 平台 = 10 查询） |
| 命中检测 | 10 查询：命中 5、未命中 5、错误 0，覆盖率 5/5 |
| 点卡扣减 | 精确扣减 10 点（99935 → 99925），流水完整 |
| 报告生成 | 7 天报告正常（75 查询、出现率 37.3%、各平台表现表） |
| 仪表盘 | KPI / 覆盖横幅 / 排名 TOP10 / 排名分布均正常 |

**检验中顺带修复 1 个 bug**：仪表盘「排名监测 TOP10」的 `check_time` 字段，因 SQLite 聚合 `max(created_at)` 返回字符串扫描到 `time.Time` 失败，导致时间显示为空/零值（`0001-01-01 00:00`）。已改为字符串接收并解析，修复后正确显示如 `2026-09-02 08:30`。
