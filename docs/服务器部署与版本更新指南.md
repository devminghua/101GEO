# LinkGeo 服务器部署与版本更新指南

> 目标：把 LinkGeo 部署到 Linux 服务器，并在后续版本迭代时**不覆盖、不丢失原有数据库资料**（客户数据、API Key、卡密、上传文件等）。

---

## 零、最简单的方法（推荐，只需一条命令）

**不用装 Docker**——因为 LinkGeo 后端是单文件程序（前端已经打包进去了），一个文件就能跑。全部流程封装成了 `scripts/deploy.sh`，你只需要：

```bash
# 1. 第一次：给服务器配 SSH 免密登录（只做一次）
ssh-copy-id root@服务器IP

# 2. 一键部署（首次部署 和 以后每次更新，都是这一条命令）
bash scripts/deploy.sh 服务器IP
```

脚本自动完成 5 件事：**编译 Linux 程序 → 上传服务器 → 备份旧数据库 → 替换程序 → 重启 + 验证**。

- 数据存在服务器的 `/opt/linkgeo/`（数据库 `geotool.db` + 上传文件 `uploads/`），更新时自动备份到 `backups/`，**数据永不丢失**。
- 首次部署还会自动装 systemd 服务（开机自启 + 崩溃自动重启）。

> 服务器是 ARM 架构（阿里云倚天 / 腾讯云 ARM 机型）就加个参数：`bash scripts/deploy.sh 服务器IP arm64`
> 默认按 x86_64 编译，覆盖绝大多数云服务器。

---

下面是**手动 Docker 方式**的详细说明（如果你更习惯 Docker，或想自己掌控每一步）。

---

## 一、先搞懂：数据存在哪、为什么不丢

整个系统只有两类数据需要保护，它们都**存在宿主机磁盘**，不在容器里：

| 数据 | 宿主机路径 | 容器内路径（挂载） |
|---|---|---|
| 数据库（客户/账号/API Key/卡密/巡检结果等一切） | `geo-tool/backend/geo-tool.db` | `/app/backend/geo-tool.db` |
| 上传文件（Logo/头像/创作图片等） | `geo-tool/uploads/` | `/app/backend/uploads` |

**核心原则**：
- 容器（甚至整个 Docker）删了重装，只要 `backend/geo-tool.db` 和 `uploads/` 这两个还在，数据就**一分不丢**。
- 更新版本 = 重建「容器/镜像」，**永远不碰**上面两个数据文件。

## 二、首次部署（服务器从零装）

### 1. 服务器装 Docker（以 Ubuntu/Debian 为例）

```bash
curl -fsSL https://get.docker.com | sh
# 启动并设开机自启
systemctl enable --now docker
# 验证
docker --version && docker compose version
```

> 国内服务器可给 Docker 配镜像加速器（阿里云容器镜像服务里免费领地址，写到 `/etc/docker/daemon.json`）。

### 2. 上传代码

任选一种：
```bash
# 方式 A：git 拉取（推荐，以后更新方便）
cd /opt && git clone <你的仓库地址> geo-tool

# 方式 B：直接上传
# 把本机 geo-tool/ 整个目录（源码包 LinkGeo-源码-20260903.zip 解压）上传到 /opt/geo-tool
```

### 3. 改服务器专属配置（重要！）

打开 `geo-tool/docker-compose.yml`，改两处：

```yaml
environment:
  # ① 百度抓取代理：host.docker.internal 只在本地 Docker Desktop 有效，
  #    服务器上要么删掉这行（走容器直连），要么改成服务器上转发服务的地址
  # GEO_BAIDU_PROXY: "http://host.docker.internal:18888"   ← 服务器上注释/删除
  # ② 密钥保持和本机一致（不要改，否则老数据解不开）
  GEO_JWT_SECRET: "f576bc1106dd00fa95909deafe599ada9dcfeef51fc9663bf8ef8f792540091e"
  GEO_SECRET_KEY: "dfb747ea472e22c831b1c65c38af0fd752d8df8e05a97bad1ddb910602ba8263"
```

### 4. 构建并启动

```bash
cd /opt/geo-tool
docker compose up -d --build
# 首次构建要拉基础镜像 + 下载依赖，约 5-10 分钟，耐心等
```

### 5. 验证

```bash
docker compose ps                 # 看到 geotool 状态 Up
curl http://localhost:8080/api/system/info   # 返回 JSON 即正常
# 浏览器访问 http://服务器公网IP:8080
```

> 登录账号：admin / ymh@0921tT（总后台）

## 三、版本更新迭代（核心：数据不丢）

**每次发新版，就这 4 步，数据绝对不丢：**

```bash
cd /opt/geo-tool

# 第 1 步：更新代码
git pull        # 或 覆盖上传新源码（backend/ frontend/ 等，别覆盖 backend/geo-tool.db）

# 第 2 步：备份数据库（铁律，每次更新前必做）
bash scripts/backup-db.sh all     # 看到 [OK] 才算成功

# 第 3 步：重建镜像 + 重启（数据在宿主机，重建不碰它）
docker compose build
docker compose up -d

# 第 4 步：验证
curl http://localhost:8080/api/system/info
```

**为什么不会丢数据**：`docker compose up -d` 只重建容器、替换镜像，`backend/geo-tool.db` 和 `uploads/` 作为 bind mount 原封不动，所以客户数据、API Key、卡密全都在。

## 四、数据备份与恢复

### 自动备份（推荐，配一次一劳永逸）

```bash
# 每天凌晨 3 点自动备份（滚动保留 20 份）
crontab -e
# 加入这一行：
0 3 * * * cd /opt/geo-tool && bash scripts/backup-db.sh all >> backups/cron.log 2>&1
```

备份文件落在 `geo-tool/backups/{dev,docker}/geo-tool-时间戳.db`。

### 手动备份

```bash
cd /opt/geo-tool
bash scripts/backup-db.sh all
```

### 恢复（万一数据出问题）

```bash
# 1. 停服务
docker compose stop geotool
# 2. 用备份覆盖当前库
cp backups/docker/geo-tool-XXXX.db backend/geo-tool.db
# 3. 重启
docker compose start geotool
```

## 五、关键注意事项（血泪教训，务必看）

1. **千万别删这两个**：`backend/geo-tool.db`（数据库）、`uploads/`（上传文件）。删了客户数据、API Key 全没。
2. **密钥别乱改**：`GEO_JWT_SECRET` / `GEO_SECRET_KEY` 一旦改了，老数据库里的 API Key、密码（enc:v1 加密）就解不开，看起来像「Key 全丢了」。要换密钥必须先重加密存量数据。
3. **更新前先备份**：这是铁律，`backup-db.sh all` 看到 `[OK]` 再动。
4. **备份要从容器内做**：`backup-db.sh docker` 已经用容器内 `.backup` 方式，别手动 `cp` 挂载的库文件（WAL 下宿主机读到的是陈旧视图，会漏数据）。
5. **百度代理**：服务器上 `GEO_BAIDU_PROXY` 的 `host.docker.internal` 是本地专用，服务器要删掉或改成真实转发地址，否则百度分析会「网络不可用」。
6. **端口**：默认 8080，云服务器记得在安全组/防火墙放行 8080。
7. **HTTPS/域名**：如需正式对外（https://你的域名），在服务器前面加 Nginx/Caddy 反代即可，数据库仍在本机不动。

---

## 六、一句话总结

- **部署**：装 Docker → 传代码 → 改代理配置 → `docker compose up -d --build`。
- **更新**：`git pull` → `backup-db.sh all`（备份）→ `docker compose build && up -d`。
- **数据**：就是 `backend/geo-tool.db` + `uploads/` 两个，永删不得、重建不碰。

## 七、数据库（PostgreSQL）+ HTTPS + OrbStack 自动部署（2026-09-05 更新）

### 7.1 数据库已切换为 PostgreSQL

自 2026-09-05 起，**服务器 / SaaS 模式默认使用 PostgreSQL**（单机版 Windows/Mac 仍用 SQLite）。

- 驱动由环境变量决定：`GEO_DB_DRIVER=postgres` 用 PG，默认 `sqlite`。
- 连接串：`GEO_DB_DSN="host=postgres port=5432 user=postgres password=<强密码> dbname=geotool sslmode=disable"`。
- `docker-compose.yml` 内置 `postgres:16-alpine` 服务，数据持久化到 `./pgdata/`。
- **PG 不映射端口到宿主机**（仅 docker 内网 hostname=postgres 访问），避免数据库暴露公网。
- PG 密码是 48 位强随机（已写进 `docker-compose.yml`），**勿提交到公开仓库**，建议迁移到 `.env`。

数据迁移（SQLite → PG）用一次性工具：

```bash
cd backend
GEO_SRC_DB="$(pwd)/geo-tool.db" \
GEO_DB_DSN="host=127.0.0.1 port=5432 user=postgres password=<密码> dbname=geotool sslmode=disable" \
go run ./cmd/migrate
```

### 7.2 ⚠️ 待办：HTTPS / 反向代理（生产必须）

当前为 HTTP（8080）。正式对外前，在服务器加一层 HTTPS 反向代理：

```nginx
# /etc/nginx/sites-available/linkgeo（示例）
server {
    listen 443 ssl http2;
    server_name geo.你的域名.com;
    ssl_certificate     /etc/ssl/linkgeo.crt;
    ssl_certificate_key /etc/ssl/linkgeo.key;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
server {
    listen 80;
    server_name geo.你的域名.com;
    return 301 https://$host$request_uri;
}
```

- 证书可用 Let's Encrypt（certbot）免费签发并自动续期。
- **微信小程序强制 HTTPS**，上小程序前必须完成此步。

### 7.3 本地 OrbStack 自动部署（每次更新完跑这一条）

本地开发用 OrbStack 跑容器时，更新完代码后一键自动部署：

```bash
bash scripts/deploy-orbstack.sh
```

脚本自动完成：备份 PG（pg_dump → backups/pg/）→ 构建前端 → 同步内嵌产物 → 重建镜像 → 重启容器 → 健康验证。

> 前端已内嵌进后端二进制（go:embed webdist），所以**前端改动也必须走这个脚本**（或手动 rsync 后 go build），不能只刷新浏览器。
