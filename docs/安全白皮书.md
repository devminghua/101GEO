# LinkGeo 系统安全审计白皮书

> 审计对象：LinkGeo（后端 Go + Gin + GORM + PostgreSQL，前端 React + Vite）
> 审计时间：2026-09-06（在 09-04 版本基础上更新）
> 审计方式：源码静态审计 + 关键链路实测
> 结论先行：**登录/注册防暴力破解已建立四层纵深防御，在线爆破不可行；核心残余风险为密码可逆存储与弱密码策略。**

---

## 一、本次审计重点：登录 / 注册防暴力破解

### 1.1 登录防护 —— 四层纵深防御

```
请求 → ① IP 限流 → ② 滑块验证 → ③ 分级锁定 → ④ 密码校验
```

#### ① IP 维度限流（挡「单 IP 高频爆破」）
- 同一 IP **60 秒最多 10 次**登录尝试，超限返回 429（`handlers/rate_limit.go`）。
- 内存实现、重启清零，属「软限流」。

#### ② 滑块验证码（挡「自动化脚本」）
- 一次性凭证（TTL 5 分钟，验证后立即作废）。
- 校验：拖到终点（容差 4px）+ 轨迹像真人（≥4 采样点、首点近起点、末点近终点、相邻位移非匀速）。
- 作用：挡掉「直接 POST 伪造 slide_x」的脚本（`services/captcha/`）。

#### ③ 分级锁定（挡「单账号+IP 爆破」）—— 关键防线
- **同一「账号+IP」连续输错 3 次 → 锁定 5 分钟**。
- **再次连续输错 3 次 → 锁定 1 小时**（升级惩罚）。
- 状态**持久化于数据库**（`login_guards` 表），重启 / 多实例不丢失。
- 锁定到期自动解除但保留累计次数（升级惩罚）；24 小时无活动惰性清理。

#### ④ 密码校验 + 统一错误提示
- 「账号不存在」「密码错误」返回**相同文案**「账号或密码错误」，防账号枚举。
- 每次登录成功/失败均记录审计日志（`login_logs`，含 IP / 状态 / 原因）。

### 1.2 防爆破效果评估

| 攻击手法 | 是否可被绕过 | 兜底 |
|---|---|---|
| 已知账号 + 固定 IP 爆破 | ❌ 3 次触发 5 分钟锁 | 分级锁定 |
| 换 IP 绕过锁定 | ❌ 每 IP 60 秒 10 次 | IP 限流 |
| 自动化脚本 | ❌ 滑块轨迹校验 | 滑块验证 |
| 撞库（多账号同 IP） | ❌ 每个账号独立锁定 + IP 限流 | 双重 |

**结论：在线暴力破解不可行。**

### 1.3 注册防护

| 防护 | 实现 |
|---|---|
| 短信验证码 | 注册需短信验证（可后台关闭）；发送接口 10 分钟 20 次/IP 限流 + 单手机号发送频率控制 |
| 注册限流 | 同一 IP **10 分钟最多 20 次**注册尝试 |
| 手机号唯一 | 全局唯一，重复注册直接拦截 |
| 手机号格式 | 正则校验（11 位、1 开头、3-9 第二位）|

## 二、安全架构评估（已达标项）

### 2.1 认证与会话
- **JWT**：HS256（HMAC-SHA256）签名，密钥来自 `GEO_JWT_SECRET`，有效期 7 天。
- 签名校验使用 `hmac.Equal` 常量时间比较，**防时序侧信道攻击**。
- 密码存储为 `enc:v1`（AES-256-GCM，随机 nonce，密钥经 SHA256 派生），非明文、非弱哈希。

### 2.2 授权与隔离
- 中间件链：`AuthRequired → LicenseGuard → FeatureGuard`，逐层校验。
- 角色控制：`SuperRequired`（仅总后台）/ `AdminOnly`（总后台+分站，拒绝 AI 优化员）。
- 数据按 `tenant_id` 租户隔离，跨租户越权访问有约束。

### 2.3 SQL 注入防护
- 数据访问统一走 GORM 参数化；原生 SQL（UPSERT、统计）也全部使用 `?` 占位符，**未发现字符串拼接 SQL**。

### 2.4 卡密授权（单机版）
- **Ed25519 非对称验签**：私钥由老板保管，客户端仅内置公钥，无法伪造卡密。
- Activation 记录附加 HMAC-SHA256 签名，**防直接改库篡改**到期时间。

### 2.5 支付回调
- 微信/支付宝回调由官方 SDK 验签，验签失败不入账；幂等入账防重复。

### 2.6 文件上传
- 类型白名单（png/jpg/jpeg/webp/gif，**已移除 SVG**）+ 5MB 限制 + 时间戳重命名（防路径遍历）。

### 2.7 前端 XSS
- 未使用 `dangerouslySetInnerHTML` / `innerHTML` / `eval`，React 默认转义，XSS 风险低。

## 三、风险清单

### 🔴 高风险

| # | 风险 | 说明 | 处置 |
|---|---|---|---|
| H1 | **密码可逆存储** | 密码用 AES-256-GCM 可逆加密（为满足 SaaS「小眼睛」查看明文），`GEO_SECRET_KEY` 泄露则全部密码/API Key 明文可解。 | 密钥严格保管、备份加密、定期轮换（业务需要，无法改为纯哈希）|

### 🟠 中风险

| # | 风险 | 说明 | 处置 |
|---|---|---|---|
| M1 | **密码策略过弱** | 注册/建号/改密均仅要求「≥6 位」，无复杂度要求，易被字典攻击。 | 提升至 ≥8 位且须含字母+数字 |
| M2 | **JWT 无登出失效/无刷新** | token 7 天内有效，改密/禁用后旧 token 仍可用。 | 服务端黑名单或缩短有效期 |
| M3 | **账号状态枚举（轻微）** | 「账号已停用」「账号已到期」返回独立文案，可据此探测账号是否存在。 | 统一为「账号或密码错误」，状态登录后告知 |
| M4 | **前端依赖漏洞** | 09-04 审计 `npm audit` 检出 echarts XSS、react-router 开放重定向等 moderate 漏洞。 | 升级 echarts@6.x / react-router@7.x 并回归测试 |

### 🟢 低风险

| # | 风险 | 说明 |
|---|---|---|
| L1 | 滑块验证码无图像 | 固定行程，脚本可伪造轨迹；但叠加 IP 限流 + 分级锁定后可接受 |
| L2 | 限流器/短信验证码内存存储 | 重启清零；多实例需改 Redis |
| L3 | 登录日志含 IP | 隐私相关，属正常审计需要 |
| L4 | HTTP 明文 | 默认 HTTP，需反代加 TLS |

### ✅ 已修复项（相对 09-04 版本）

| 项 | 说明 |
|---|---|
| 默认密钥回退 | 服务器模式未配置强密钥会**直接拒绝启动**（`log.Fatalf`），杜绝弱密钥上线 |
| SVG 上传 XSS | Logo 上传白名单已移除 `.svg` |
| 数据库架构 | 已由 SQLite 全量迁移至 PostgreSQL |

## 四、修复建议（按优先级）

### R1（P0）密码强度提升
注册 / 建号 / 改密 / 卡密激活，统一要求密码 ≥8 位且须同时包含字母与数字（前后端同步校验）。

### R2（P1）JWT 登出失效
服务端维护已登出 token 黑名单（或引入 refresh token + 短 access token）。

### R3（P1）账号状态枚举收敛
「停用」「到期」也返回统一「账号或密码错误」，具体状态在登录成功后或联系后台告知。

### R4（P1）依赖升级
```bash
cd frontend && npm audit fix --force   # echarts@6.x / react-router-dom@7.x
```
升级后回归：仪表盘图表（echarts）、全部路由跳转（react-router）。

### R5（P2）可选加固
- 滑块升级为带图像/行为验证码（极验/阿里云验证码）。
- 登录响应头补安全头（`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`）——建议由反代层统一加。

## 五、部署安全基线

1. ✅ 强密钥已配置：`GEO_JWT_SECRET`、`GEO_SECRET_KEY` 强随机（docker-compose 已固化，勿改回默认）。
2. ✅ HTTPS 反代：Nginx/Caddy 启用 TLS，后端 8080 仅内网。
3. ✅ 防火墙最小开放：云安全组只放 80/443，不暴露 8080/5432；SSH 限来源 IP。
4. ✅ 敏感文件加固：`.gitignore` 忽略 `.env`/`*.db`/`backups/`；卡密私钥移出项目目录。
5. ✅ 备份加密：`backups/pg/` 每日备份 + 异地存储。
6. ✅ 密钥轮换：更换 `GEO_SECRET_KEY` 前必须先重加密存量 enc:v1 数据。

## 六、总体结论

| 维度 | 评分 | 说明 |
|---|---|---|
| 登录防暴力破解 | ★★★★★ | 四层纵深防御，在线爆破不可行 |
| 注册防刷 | ★★★★★ | 短信验证 + 限流 + 唯一性 |
| 认证安全 | ★★★★★ | JWT + AES-GCM + 常量时间比较 |
| 授权隔离 | ★★★★★ | 三级中间件 + 角色 + 租户隔离 |
| 数据安全 | ★★★★☆ | 参数化 SQL；扣分项为密码可逆存储（业务需要）|
| 密码策略 | ★★☆☆☆ | 仅 6 位无复杂度，**建议优先加固（R1）** |

**综合判断：** 系统对「暴力破解」的防护是**到位且可靠的**；在完成 R1（密码强度）后，可安全部署到生产服务器。其余项（JWT 黑名单、账号枚举收敛）建议随迭代跟进。
