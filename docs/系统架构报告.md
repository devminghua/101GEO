# LinkGeo · 生成式引擎优化平台 — 系统架构报告

> 版本：v1.0　日期：2026-09-03　撰写：十一的前男友

> 范围：功能全景、技术栈、总体架构、数据模型、安全设计、部署形态

---

## 一、产品概述

**LinkGeo（生成式引擎优化平台，Generative Engine Optimization）** 是一套面向企业客户的 **GEO 监测 SaaS**：

- **核心价值**：监控品牌在各类 AI 平台（DeepSeek、豆包、通义、智谱、Kimi、OpenAI 等）生成式回答中的被提及情况，量化 GEO 优化效果，输出可落地的优化建议。
- **商业模式**：多租户 SaaS，**「一个客户 = 一个分站 + 一个登录账号」**，通过点卡充值（7000×3 天试用 + 3000×12 个月）与续费机制变现。
- **目标用户**：需要让自家品牌被 AI 搜索引擎优先推荐的行业客户（当前重点落地婚恋行业）。

系统并非单一「关键词监测工具」，而是在此基础上扩展为 **「监测 + 诊断 + 获客 + 创作 + 投放」的一体化平台**。

## 二、总体架构

### 2.1 架构风格

**单体后端 + 内嵌前端 + 单文件数据库** 的轻量一体化架构，追求「零配置、易部署、单机可跑、可交叉编译到任意平台」。

```
┌─────────────────────────────────────────────────────────────┐
│                        浏览器 / 客户端                         │
│              React SPA（内嵌于后端二进制中）                    │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP/JSON（REST）
┌──────────────────────────▼──────────────────────────────────┐
│                    Go 后端（单一可执行文件）                     │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  Gin 路由层（middleware：JWT 鉴权 / 角色 / 特性守卫 / 限流） │  │
│  ├────────────────────────────────────────────────────────┤  │
│  │  业务 Handler 层（auth/keyword/platform/task/dashboard…） │  │
│  ├────────────────────────────────────────────────────────┤  │
│  │  Service 层（AI 客户端 / GEO 巡检 / 百度抓取 / 抖音 / 小红书 /  │  │
│  │           创作 / 内容 / 支付 / 通知 / 短信 / 加密 / 头像）      │  │
│  ├────────────────────────────────────────────────────────┤  │
│  │  数据访问层 GORM（多租户 tenant_id 隔离）                     │  │
│  └────────────────────────────────────────────────────────┘  │
│        │                          │                          │
│        ▼                          ▼                          │
│  SQLite 单文件库            外部 AI 平台（OpenAI 兼容协议）        │
│  （WAL / 单连接池）          微信 / 支付宝支付回调                  │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 架构特点

| 特点 | 说明 |
|---|---|
| **单二进制** | 前端 `dist` 通过 `go:embed` 内嵌进后端，一个 exe 即完整服务，无外部静态资源依赖 |
| **数据目录解耦** | 数据库/uploads 统一走 `DataDir`（Windows=`%LOCALAPPDATA%\LinkGeo`，其它平台=`.`），与工作目录彻底解耦，杜绝「安装后相对路径失效即崩溃」 |
| **零配置首启** | 首次启动自动建库 + 自动迁移 49 张表 + 写入种子数据（admin/demo 账号、平台模板、默认关键词、风险词库等） |
| **纯 Go 无 CGO** | SQLite 用 `glebarez/sqlite`（底层 `modernc.org/sqlite`），`CGO_ENABLED=0` 可交叉编译到 Windows/Linux/macOS/ARM |
| **端口自愈** | 默认端口被占用时自动顺延（最多 +20），避免客户机端口冲突导致启动崩溃 |
| **多形态交付** | 同一份代码产出：Docker 容器 / Windows 标准安装器 / Windows 绿色便携版 |

### 3.3 AI 接入

- **统一 OpenAI 兼容客户端**（`services/ai/client.go`）：内置 10+ 平台模板（OpenAI / DeepSeek / Kimi / 通义千问 / 智谱 GLM / 豆包 / 腾讯混元 / Ollama / Grok / Claude 等），任意 OpenAI 兼容 HTTP 服务均可接入。
- 通过 `base_url + api_key + model` 三要素统一配置，支持连接测试。

### 3.4 数据存储

- **SQLite 单文件数据库**（`geo-tool.db`）。
- 并发安全：`journal_mode(WAL)` + `synchronous(NORMAL)` + `busy_timeout(5000)` + 单连接池（规避 SQLITE_BUSY）。
- 无独立数据库服务，无需运维，天然适合单机/容器/客户端三种形态。

### 3.5 部署形态

| 形态 | 说明 |
|---|---|
| Docker 容器 | `docker-compose.yml` 单容器，端口 8080，bind mount 持久化数据库与 uploads |
| Windows 安装器 | `LinkGeo-Setup.exe`（NSIS），装到 Program Files，数据落 `%LOCALAPPDATA%\LinkGeo`，支持卸载 |
| Windows 绿色版 | `LinkGeo-便携版.zip`，解压即用，数据跟随 exe（`data\` 目录） |

## 四、功能模块详解

### 4.1 认证与权限（多角色 RBAC）

- 登录：用户名/密码 + **滑块验证码**（防机器人）+ JWT Token。
- 三种角色：
  - **super**（总后台管理员，tenant_id=0）：跨租户，管理所有分站、平台、用户、支付。
  - **admin**（分站管理员）：仅本租户，可配置关键词、查看数据、充值、管理 AI 优化员。
  - **operator**（AI 优化员）：受限账号，无配置/审计权限。
- 登录日志、登录防护（LoginGuard）、有效期校验（到期禁用）。
- **自助注册**：手机号 + 短信验证码（当前 Mock）→ 自动建分站 + 开 7 天试用 + 100 点 + 直接签发 Token 登录。

### 4.2 多租户 SaaS

- `Tenant` 分站模型，所有业务数据带 `tenant_id` 隔离。
- 总后台「融合客户管理」：**一个客户 = 一个分站 + 一个登录账号**，一键开通/列表/查询/模拟登录。
- 续费/延长开通时长、续费流水对账。

### 4.3 GEO 巡检核心（监测引擎）

- **关键词监控**：监控问题 CRUD、品牌词配置、分类、启用控制、批量导入。
- **AI 平台管理**：10+ 模板、自定义 OpenAI 兼容服务、连接测试。
- **巡检任务**：一键全量巡检 → 并发调用所有启用平台，检测品牌词是否在回答中被命中，产出命中/未命中/错误分 Tab 明细。
- **查询结果**：全量明细，按平台/结果/关键词过滤。

### 4.4 仪表盘

今日查询量、品牌出现率、命中平台数、累计出现率、近 30 天趋势、各平台命中率、监控问题命中率排行、最近任务。

### 4.5 GEO 智能中心（诊断 + 行动）

- 品牌事实库（可被 AI 正确引用的结构化事实）
- 竞品库（竞品监测与对比）
- 引用溯源（citations，品牌被引用的域名来源）
- 风险词库（命中即代表回答存在幻觉/过度承诺/合规风险）
- 六项核心指标 & 缺口分析（geo/intel、geo/gaps）
- 优化行动清单（自动生成 + 增删改）
- 网站 GEO 审计（geo/audit）+ LLMS.txt 生成器 + Schema 结构化数据生成器

### 4.6 百度关键词分析

- 百度 SERP 抓取（深度固定 3 页）+ 结果解析（标题/URL/摘要/排名）。
- 客户网站配置、监控关键词配置、排名历史快照。
- 反爬策略：代理转发（可回落直连）+ 错误分类 + 频率管控（待进一步加固）。

### 4.7 抖音获客

账号管理、同行追踪、视频数据、客户获取（leads + 解析）、话术库、频率与安全设置、动作前置校验、半自动打招呼、动作日志。

### 4.8 小红书获客

账号管理、同行追踪、笔记数据、客户获取、话术库、**AI 话术生成**、频率与安全、半自动打招呼、价值统计、通知管理员、动作日志。

### 4.9 智能创作中心

角色设定（≥6 内置角色）、AI 多轮对话、文案写作、抖音热门视频脚本、小红书热门文案、深度学习再创作、洗稿（去重保意）、图片生成、生成记录 & 素材库。

### 4.10 内容投放

媒体库、软文生成（AI 写软文）、发布任务（自动/半自动）、监控记录、发稿平台配置、效果分析。

### 4.11 点卡充值体系

- 点数余额与流水（points）。
- 自助扫码充值：微信 Native / 支付宝当面付，下单 + 轮询状态。
- 支付回调验签 + 幂等入账（RechargeOrder / PayCallbackLog）。
- 总后台可手动为分站充值点数并记录流水。

### 4.12 站内信

SaaS 端统一推送，客户端按 `user / tenant / all` 范围匹配，未读数、已读标记、一键全部已读。

### 4.13 报告

一键生成近 7/14/30 天 Markdown 周报（含各平台表现与优化建议），支持导出。

### 4.14 定时任务（后台调度）

- **自动巡检**：cron 定时器，8:00–22:00 时段为所有启用分站各触发一轮巡检（默认 60 分钟）。
- **每日告警推送**：到期预警 + 点数不足，每小时检查一次到点推送。
- **超时订单关闭**：关闭超时未支付的充值订单。
- **僵尸任务回收**：启动时回收上次中断遗留的巡检任务。

## 六、安全设计

| 层面 | 措施 |
|---|---|
| 鉴权 | JWT（可配置 `GEO_JWT_SECRET`）、角色中间件（SuperRequired / AdminOnly / FeatureGuard） |
| 防机器人 | 滑块验证码、短信验证码限流（同号 60s 冷却）、注册/IP 限流 |
| 敏感数据加密 | API Key、密码等用 `enc:v1` 可逆加密（AES 派生，密钥 `GEO_SECRET_KEY` 强随机） |
| 多租户隔离 | 全业务数据 `tenant_id` 隔离，super 跨租户、admin 仅本租户 |
| 支付安全 | 回调验签 + 幂等入账，防止重复/伪造回调 |
| 反爬 | 百度代理转发（可回落直连）+ 错误分类，SSRF 风险已标注待加固 |
| 账号枚举防护 | 重复手机号检测在验证码校验之后 |

## 八、总结

LinkGeo 采用「**Go 单体 + 内嵌前端 + SQLite 单文件**」的轻量架构，以极低运维成本支撑了 **GEO 监测核心 + 智能诊断 + 双平台获客 + 内容创作投放 + 点卡商业化** 的完整业务闭环，并通过纯 Go 交叉编译实现 **Docker / Windows 安装器 / Windows 便携版** 三形态一键交付。

**技术栈一句话**：Go 1.24 + Gin + GORM + SQLite（纯 Go 无 CGO）｜React 18 + TypeScript + Vite + Arco Design + ECharts｜OpenAI 兼容多平台 AI 接入｜微信/支付宝扫码支付。
