# LinkGeo 授权加固实施方案（卡密 + 防破解）

> 版本：v1.0　日期：2026-09-03　撰写：太湖一号
> 状态：老板已拍板方向，进入实施

---

## 一、背景与目标

**问题**：当前 Windows 客户端三层均未加密——exe 未加壳、数据库明文、授权（有效期/功能/点数）纯本地明文校验，破解者改一个数据库字段即可永久白嫖。

**目标**：把破解门槛从「改字段零门槛」提升到「需要专业逆向工程师」，并建立 10000 张卡密（7000×3 天试用 + 3000×12 个月）的授权体系。

**老板拍板的三个方向**：

1. **软件级卡密激活** —— 客户拿到单机版必须输卡密激活才能用，激活前锁定；super 密码老板另设随机值，不随包下发。
2. **先做 P0 + 离线卡密，在线后补** —— 不依赖公网；等有公网服务器再上在线心跳。
3. **独立离线卡密** —— 老板后台批量生成导出，与点卡充值并存（点卡管充值、卡密管开通时长）。

## 二、总体方案

```
┌─────────────────────────────────────────────────────────────┐
│  老板总后台（super）                                          │
│  ┌───────────────┐   私钥(Ed25519)    ┌──────────────────┐   │
│  │ 卡密批量生成   │ ─────────────────▶ │ 卡密导出 txt/csv  │   │
│  └───────────────┘                     └──────────────────┘   │
└─────────────────────────────────────────────────────────────┘
                            │ 卡密串（离线交付）
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Windows 客户端（内置公钥，无私钥）                            │
│  首次启动 → 未激活锁定 → 输入卡密 → 公钥验签 → 开通时长          │
│  （3 天试用 / 12 个月），首次激活开始计时                        │
└─────────────────────────────────────────────────────────────┘
```

**核心原理**：卡密 = 授权数据 + **非对称签名**。私钥只在老板后台，客户端只有公钥 → **卡密不可伪造、不可枚举**，但客户端无法自己"造卡密"。

---

## 三、卡密设计

### 3.1 签名算法

- **Ed25519**（Go 标准库 `crypto/ed25519` 原生支持，无额外依赖，签名快、密钥短）。
- 私钥 64 字节、公钥 32 字节、签名 64 字节。

### 3.2 卡密数据结构

| 字段 | 长度 | 说明 |
|---|---|---|
| card_id | 4 字节 | 卡密序号（自增，防重复激活） |
| tier | 1 字节 | 1=3 天试用、2=12 个月 |
| nonce | 8 字节 | 随机数（防枚举/防重） |
| signature | 64 字节 | `Ed25519_Sign(私钥, card_id ‖ tier ‖ nonce)` |

合计 77 字节 → **Base32 编码**（去除易混字符 I/L/O/U/0/1）→ 分组加连字符。

### 3.3 卡密串格式

```
LG-XXXXX-XXXXX-XXXXX-XXXXX-XXXXX-XXXXX-XXXXX
```

约 25 组 5 位字符，前缀 `LG-` 便于识别。支持 `-`/空格分隔、大小写不敏感、去分隔符解析。

### 3.4 激活规则

1. 解码卡密串 → 得到 card_id / tier / nonce / signature。
2. **公钥验签**：`Ed25519_Verify(公钥, card_id‖tier‖nonce, signature)`，不通过 → 拒绝。
3. **防重复激活**：本地记录已激活的 card_id，重复 → 拒绝。
4. 验签通过 → 按 tier 开通：3 天 / 12 个月，**以激活时刻为起点计时**（首次激活生效，防囤卡）。

## 四、软件级激活锁定

### 4.1 未激活状态

- Windows 单机版首次启动，数据库为空 → 进入**未激活状态**。
- 未激活时：仅开放「激活」入口（输入卡密），所有业务功能锁定（前端只渲染激活页 + 后端业务接口拒绝）。
- 激活成功后：自动建库、初始化、进入正常使用。

### 4.2 super 密码随机化

- 不再随包下发 `admin/admin123` 公开密码。
- super 密码由**激活流程自动生成随机值**，展示给激活者（客户），或老板后台指定。
- 保证客户拿不到 super 权限，授权锁死在「激活有效期」层面。

### 4.3 激活状态持久化

- 新增激活状态表（或复用现有 setting），记录：是否已激活、card_id、激活时间、到期时间、机器码。
- 到期后：进入「已到期」状态，禁止登录业务，提示续费。

## 五、P0 本地加固（防改库）

### 5.1 授权数据 HMAC 签名防篡改

- 将 `expire_at + features + points + activated 状态` 打包，用 **HMAC-SHA256**（密钥派生自 `GEO_SECRET_KEY`）计算签名，落库存储。
- 登录/功能校验时重新计算签名比对，不一致 → 判定数据被篡改，拒绝服务。
- 效果：**用 DB Browser 直接改字段不再生效**（改了签名对不上）。

### 5.2 Windows 客户端注入独立随机密钥

- 打包时向 `.env` 注入**随机生成的 `GEO_SECRET_KEY`**，替换代码里的默认密钥 `geo-tool-dev-payload-secret`。
- 保证 enc:v1 可逆加密不再「全网一个默认密钥」。

## 六、后台卡密管理（总后台 super）

新增「卡密管理」页面：

- **批量生成**：选择类型（3 天试用 / 12 个月）+ 数量 → 生成卡密串。
- **导出**：txt / csv 批量导出（含卡密串、类型、状态）。
- **列表**：已生成卡密的卡密 ID、类型、生成时间、状态（未激活/已激活/激活时间/机器码）。
- **私钥安全**：私钥用 `GEO_SECRET_KEY` 加密后存库，仅生成卡密时解密使用。

## 七、安全边界（诚实说明，不口嗨）

| 威胁 | 能否防住 | 说明 |
|---|---|---|
| 改数据库字段（expire_at/points/features）白嫖 | ✅ 能 | P0 HMAC 签名防篡改 |
| 伪造卡密 / 枚举卡密 | ✅ 能 | Ed25519 非对称签名，无私钥无法伪造 |
| 重复使用同一张卡密 / 囤卡 | ✅ 能 | card_id 防重 + 首次激活计时 |
| **逆向 exe，patch 掉验签逻辑直接破解** | ❌ 防不住 | 离线软件固有局限；只能靠 P2 garble 混淆抬高门槛 |
| 提取公钥 | 无影响 | 公钥本来就公开，只能验签不能签名 |

**结论**：离线卡密方案把破解门槛从「零基础改字段」提升到「专业逆向工程师 + 反汇编 patch」，可挡住 90%+ 的普通人。**要彻底杜绝破解，必须做 P1 在线授权**（服务端决策，本地无法绕过），待公网服务器就绪后实施。

## 九、待办（P1 在线授权，等公网服务器）

- 卡密激活改为**联网验签**（客户端 → 授权服务器 → 验卡密 + 签发带签名的授权 token）。
- **机器码绑定**：一卡密一机（采集 CPU/硬盘/主板序列号哈希）。
- **定期心跳**：客户端定期联网校验授权有效性，离线超时锁定。
- 授权服务器可复用 SaaS 总后台加一个公网域名，或独立部署云函数/轻量服务器。
