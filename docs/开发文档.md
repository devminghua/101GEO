## 一、项目概述

**LinkGeo（生成式引擎优化平台，Generative Engine Optimization）** 是一套面向企业的 GEO 监测与获客 SaaS。

- **核心价值**：监测品牌在各类 AI 大模型（DeepSeek、豆包、Kimi、通义、智谱 GLM、腾讯混元等）回答中的被提及情况，量化 GEO 优化效果，并打通「监测 → 创作 → 获客」闭环。
- **品牌**：`Link`（深色 `#1D2129`）+ `Geo`（紫蓝 `#4F46E5`），副标题「生成式引擎优化平台」。
- **商业模式**：多租户 SaaS + 单机版（Windows/Mac，卡密授权）+ 服务器版，Token 计费变现。

**代码规模**：后端约 2 万行 Go，前端约 1.5 万行 TS/TSX。

## 三、系统架构

- **单二进制部署**：前端构建产物 `frontend/dist` 同步到 `backend/webdist`，由 `//go:embed webdist` 内嵌进 Go 二进制，一个文件即可跑。
- **多租户**：`tenant_id` 隔离数据；总后台（super/tenant_id=0）统一管理，分站（tenant_id>0）独立运营。
- **双数据库模式**（`database.Init` 按 `GEO_LICENSE_MODE` 分支）：
  - **服务器/SaaS 版**（license_mode=false）：PostgreSQL，`GEO_DB_DRIVER=postgres` + `GEO_DB_DSN` 必填，缺 DSN 拒绝启动。
  - **单机版**（license_mode=true）：SQLite 本地文件 `geo-tool.db`，客户单机无需装 PG。

```
浏览器 → 后端(Gin, 单二进制) → PostgreSQL(服务器) / SQLite(单机)
                ├── /api/*         业务接口（登录 + 中间件鉴权）
                ├── /uploads       上传文件静态目录
                ├── /assets        内嵌前端静态资源
                └── /notify/*      微信/支付宝支付回调
```

## 七、关键实现

### 7.1 认证与授权
- **JWT**：HS256 签名，密钥 `GEO_JWT_SECRET`，7 天有效，`hmac.Equal` 常量时间比较。
- **密码**：`enc:v1` 可逆加密（AES-256-GCM，密钥经 `GEO_SECRET_KEY` SHA256 派生）。
- **中间件链**：`AuthRequired → LicenseGuard → FeatureGuard`；角色控制 `SuperRequired` / `AdminOnly`。
- **防爆破**：滑块验证 + 同账号同 IP 连错 3 次锁 5 分钟（再错锁 1 小时）+ IP 限流 + 防账号枚举。

### 7.2 Token 计费与充值
- AI 调用按次扣 1 token（`points.DeductOne`）。
- **双通道充值（二选一）**：
  - 扫码充值（微信 Native / 支付宝当面付，下单 → 二维码 → 轮询到账）。
  - 卡密兑换（充值卡密 `tier=3` → 验签 → 事务入账 + 标记已用，防重复兑换）。

### 7.3 卡密体系（Ed25519）
- 卡密 = `card_id(4) + tier(1) + nonce(8)` + Ed25519 签名，格式 `LG-XXXXX-...`。
- 类型：`tier=1` 3 天试用、`tier=2` 12 个月、`tier=3` 充值 token。
- 私钥老板持有（enc:v1 加密存 `settings`），客户端内置公钥验签，**不可伪造**。
- 当前公钥 `qZ/FayAFWx9HCMdD6hwPOcWL2g2ib7TiifaSRE3M22Y=`；单机版激活后 super 密码随机化。

### 7.4 AI 平台与巡检
- 定时任务（60 分钟，8-22 点）并行向各平台提问，检测品牌是否被提及、排名。
- **平台独立**：分站完全独立配置自己的 API Key（不继承总后台全局平台）；总后台全局平台仅供总后台自用。
- 新建平台默认请求间隔 2000ms（规避限流 429）。
- 当前模型：DeepSeek(deepseek-v4-flash)、豆包(doubao-seed-evolving)、通义(qwen3.6-plus)、智谱(glm-4.7-flash)、Kimi(kimi-k2.6)、腾讯混元(hy4-preview)。

### 7.5 试用期与到期提醒
- 自助注册默认 7 天试用（`register_trial_days` 可配）；后台开客户可选手动「试用7天」。
- 顶栏 Tag 显示剩余天数（含试用客户），≤7 天红色「即将到期」。

### 7.6 帮助文档（分类 + 多文档）
- 后台维护「分类 → 文档」，客户端侧栏「使用指南」下拉（分类→文档），点文档看正文（富文本 + B 站视频自动嵌入 iframe）。

### 7.7 百度爬虫 · 同行分析
- 抓取同行站点、识别竞争品牌、竞品关键词覆盖与排名对比（深度固定 3）。

### 7.8 截流获客
- 小红书截流（AI 开场话术）、抖音截流（流量/对标账号分析）、自动打招呼。

## 九、安全设计

详见 `docs/安全白皮书.md`。要点：
- 认证：JWT + AES-GCM + 常量时间比较 + 多层防爆破。
- 数据：API Key / 密码加密落库、SQL 全参数化、文件上传类型白名单 + 时间戳重命名。
- 密钥：服务器模式漏配 `GEO_JWT_SECRET`/`GEO_SECRET_KEY` 会**拒绝启动**（防弱密钥上线）。
- 卡密：Ed25519 验签，私钥不外传，卡密不可伪造/枚举。

## 十、开发规范与坑（必读）

> 🔴 **版本迭代铁律（老板指令，永久有效，勿忘）**：老板的**每一次提交/更新 = 一次版本迭代**，版本号必须递增。当前版本号唯一定义在 `backend/config/config.go` 的 `const Version`（当前 1.0.51）。发版只改这一处，客户端与 SaaS 端「登录页 + 侧栏系统设置下方」自动显示。发版流程：改 Version → 前端 build → rsync webdist → go build → 部署/打包。**忘记更新版本号 = 违规。**

> 🔴 **「客户看不懂系统在干什么」原则（2026-09-12 起）**：凡是**系统在后台自动完成**的动作（定时巡检、闭环复测、引用采集等），都必须让客户能看见「什么时候做的、做了什么、什么结果」。客户看不到自动动作，就会认为「买了软件没干活」。已知的实现落点是 GEO 智能中心的「① 工作日志」页（`GET /api/geo/worklog`）；后续新增任何后台自动化能力，须同时在 `backend/handlers/worklog.go` 里补一条事件来源，否则该能力对客户等于不存在。

> 🔴 **「零值有业务语义的字段禁止加 `default` 标签」铁律（2026-09-12 起，永久有效）**：GORM 在 `Create` 时会**省略零值字段**，让数据库填默认值。若字段带 `gorm:"default:1"` 而又显式赋 `0`，**落库结果会是 1 而不是 0**，且**没有任何报错**。v1.0.45 实锤：`CheckResult.SampleCount` 带 `default:1`，熔断跳过的记录（应表示「未调用、不扣费」）被写成 1，导致工作日志消耗虚增 180 点、对客户对账单撒谎——**这个 bug 由 v1.0.44 的修复动作自己引入**。判断口径：**若「0」在业务上是一个有效取值（0 次、0 消耗、0 退款、0 分），就不能写 `default`**；只有「零值等价于未设置」的字段才可用。落库语义必须用 `models/checkresult_test.go` 那类**真实 SQLite 落库测试**验证，纯内存断言查不出来。**凡新增 `gorm:"default:*"` 前先自问：这个字段为 0 时业务含义是什么？**

> 🔴 **「展示口径必须与实际账本一致」铁律（2026-09-12 起）**：任何展示给客户的「消耗 / 金额 / 点数 / 次数」，都必须能由**真实账本字段**推导出来，且**每个版本都要用真机数据对账一次**（拿展示值 ÷ 流水值，差值必须可解释）。已踩两次：v1.0.42 用 `total_queries`（组合数）当消耗、低于真实账单；v1.0.44 净消耗公式本身对，但输入字段被默认值污染。**对账方法**：从 `point_records` 按 task 时间窗求 `-SUM(amount)` 得真实扣费，与 `SUM(sample_count)-SUM(refunded_points)` 比对，差额必须为 0 或有明确解释。

> 🔴 **「高频表必须建 `(tenant_id, created_at)` 复合索引」铁律（2026-09-12 起）**：本项目全部业务表按 `tenant_id` 隔离，且列表页几乎都是「按租户取最近 N 条并倒序」。**只有 `tenant_id` 单列索引时，PG 会退化为「索引取全部本租户行 + 内存排序」**，数据量上万后明显劣化（实测点卡流水 1.9ms 走 Seq Scan）。索引一律**定义在 `models` 结构体的 GORM 标签里**（`index:idx_xxx,priority:N,sort:desc`），不要只在库上裸建——否则单机版 SQLite 初始化时拿不到同一套索引，两版行为分叉。**新增列表接口前先 `EXPLAIN (ANALYZE)` 看是否出现 `Seq Scan` 或 `Sort`。**

> 🔴 **「失败必须退款」铁律（2026-09-12 起，永久有效）**：**任何扣点卡的功能，都必须在「已扣费但未取得有效结果」时退还点数**。巡检在 v1.0.44 之前只扣不退，实测一轮 274 次调用中 222 次失败仍全额扣费（累计多扣 5841 点）。判断口径：调用报错、或返回内容为空 → 退还；调用成功即使业务上「未命中」也不退（那是一次有效结论，客户拿到了信息）。已知实现：`handlers/ai_assistant.go`、`handlers/tool_parse.go`、`services/geo/checker.go`。**新增扣费点前先 grep `points.DeductOne` 看同行是否有退款分支。**

> 🔴 **「确定性故障要熔断」铁律（2026-09-12 起）**：外部依赖（AI 平台等）连续失败达阈值（当前 5 次）即应熔断跳过，**不再扣费、不再调用**。欠费、Key 失效、额度耗尽属确定性故障，重试必然继续失败，只会白烧客户点数并拖长任务（实测豆包欠费后仍被追问 93 次、任务拖到 69 分钟）。任一调用成功即清零计数，以区分「确定性故障」与「偶发抖动」。

> 🔴 **「超时保护必须能真正中断」铁律（2026-09-12 起）**：写超时保护时，**必须验证它在真机上真的触发过**（`grep` 日志确认），不能只看代码存在。巡检的 55 分钟保护曾长期形同虚设——因为组合是「阻塞式排队启动」，槽位占满后主循环永远卡在取号处，走不到超时判断，导致历史 13 个任务失控、最长 9.8 小时，全靠容器重启回收。正确做法：**任务级 `context` 贯穿所有子调用**，并让所有等待（取号、补间隔、退避重试）都可被取消。

> 🔴 **时区铁律（2026-09-12 起，永久有效）**：容器镜像默认时区是 **UTC**（`docker-compose.yml` 未设 `TZ`），Go 的 `time.Now()` 在容器里等于 UTC 时间。因此**任何「按天」「按小时」的业务逻辑一律使用 `backend/services/biztime`**（北京时间 FixedZone UTC+8），**禁止直接写 `time.Now()`**；数据库按天分组用 `database.DaySQL(col)`（已内置 `AT TIME ZONE 'Asia/Shanghai'`）。`time.Now()` 仅用于**绝对时刻**场景（耗时计时、`updated_at`、JWT 过期、限流窗口、支付订单过期等）。违反会导致客户白天不巡检、签到/配额跨天错位等只有真机跑一天才暴露的隐蔽 bug。

> 📋 **升级日志同步约定**：每轮迭代除递增版本号外，还须在第 3 步同步在 `backend/handlers/changelog.go` 的 `changelogEntries` **数组头部**插入一条新记录（`version/date/title/items`，items 的 type 取 `feature|improve|fix|security`），客户端「系统设置 → 升级日志」会自动展示，无需改数据库。三处（Version / 本文档版本记录 / changelog.go）必须同步，缺一扣分。

1. **备份铁律**：改数据/部署前先 `bash geo-tool/scripts/backup-db.sh`，见 `[OK]` 才动。
2. **密钥**：容器库 `GEO_JWT_SECRET=f576bc…`、`GEO_SECRET_KEY=dfb747…`；改密钥前必须先重加密存量 enc:v1 数据。
3. **API Key 权威源**：容器 PostgreSQL 库唯一权威；严禁开发库反向覆盖；同步单向容器库→开发库。
4. **前端改动后**：`rsync frontend/dist/ → backend/webdist/` 再 `go build`。
5. **交叉编译**：`CGO_ENABLED=0 GOOS=windows|darwin|linux GOARCH=amd64|arm64 go build -ldflags "-s -w"`（glebarez/sqlite 纯 Go 无 CGO，可交叉编译）。
6. **mac universal**：`lipo -create arm64 amd64`。
7. **NSIS**：Docker Debian + `apt install nsis`（先 `apt update`），`LC_ALL=C.UTF-8`，脚本 UTF-8 BOM。
8. **vite build**：清 dist 会触发 safe-delete 保护，先 `mv dist /tmp/xxx` 再 build。
9. **打包源文件**：放 `.build/`（`/tmp` 会被系统反复清理）。
10. **本机有代理**：curl 测本机端口加 `--noproxy '*'`。
11. **zip 中文文件名**：Linux unzip 会乱码，打包用英文文件名。
12. **单机版 .env**：必须含 `GEO_LICENSE_MODE=true` + `GEO_LICENSE_PUBLIC_KEY`，缺了单机版无法启动。

🔴 **分站（tenant_id ≠ 0）只使用自己配置的 AI 平台，不继承总后台全局平台。**

- 客户在「AI 平台」页自行添加平台并填入自己的 API Key，AI 调用费用记在客户自己的服务商账号上。
- 总后台（tenant_id = 0）使用全局平台池，仅服务总后台自身。
- 分站之间平台互不可见。
- **唯一实现处**：`backend/services/ai_platform/platform.go`。任何需要「取 AI 平台」的代码都必须调用它（`OwnPlatforms` / `FirstUsable` / `PickPreferred` / `Usable`），**禁止再各写一套查询逻辑**——2026-09-12 之前正是因为三套并存，出现同一分站不同功能从不同账号扣费的严重问题。
- 未配置平台的分站：所有 AI 功能统一返回「请先配置 AI 平台」，行为一致，不会再出现「某个功能能用、某个不能用」的困惑。
